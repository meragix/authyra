## What is Authyra?

Authyra is not another identity provider. It's the orchestration layer between your Flutter app and whatever auth infrastructure you already have, a custom API, Auth0, Firebase, Supabase, or a raw OIDC provider.

Most Flutter auth packages bundle the protocol, the identity provider, and your app's session plumbing together. Authyra sits one layer above that: it doesn't talk to any external service itself, it orchestrates the providers you configure and owns the client-side session lifecycle on top of them, sign-in, session persistence, token refresh, and multi-account state, without coupling to a backend, a navigation framework, or a UI library.

## Two packages

Authyra ships as two complementary packages:

::card-group
  :::card
  ---
  icon: i-lucide-box
  title: authyra
  to: https://pub.dev/packages/authyra
  ---
  Pure Dart. Zero Flutter dependency. Use on mobile, web, desktop, Dart backend (Shelf, Dart Frog), or CLI. Contains `AuthyraClient`, `AuthyraInstance`, `CredentialsProvider`, `SessionManager`, `AccountManager`, and all interfaces.
  :::

  :::card
  ---
  icon: i-lucide-smartphone
  title: authyra_flutter
  to: https://pub.dev/packages/authyra_flutter
  ---
  Flutter layer. Re-exports everything from `authyra`. Adds OAuth2 providers (`GoogleProvider`, `GitHubProvider`, `OAuth2Provider`, `ProxyOAuthProvider`), `SecureAuthStorage`, and `OAuth2CallbackHandler`.
  :::
::

Sign in with Apple lives in a third package, `authyra_apple`, built on the native `sign_in_with_apple` SDK rather than a browser-based OAuth2 flow. See [Apple Provider →](/providers/apple).

**Rule of thumb**: depend on `authyra_flutter` for Flutter apps. Depend on `authyra` for Dart backends, unit tests, or any non-Flutter Dart target.

## Core principles

### 1. Pure logic, no framework coupling

`AuthyraClient` is a plain Dart class, no `BuildContext`, no `ChangeNotifier`, no platform channel. The same code runs in a Flutter app and in a `dart test` suite.

### 2. Everything is an interface

`AuthProvider` and `AuthStorage` are abstract classes you implement:

- Credentials or OAuth2 plug in through the same `AuthProvider` interface. Implement it directly for a strategy Authyra doesn't ship (SAML, magic link, phone OTP, anything else).
- Any storage backend, `flutter_secure_storage`, Redis, SQLite, an in-memory map, is swappable.
- Tests replace providers and storage with three-line classes. No mocking framework needed.

### 3. Reactive by default

Every state change emits on `authStateChanges: Stream<AuthState>`. Wire it to `StreamBuilder`, Riverpod, Bloc, or a GoRouter redirect. `AuthState` uses `Equatable`, so identical consecutive states are deduplicated, no spurious rebuilds.

### 4. Synchronous state when you need it

`AuthyraInstance` (the singleton wrapper) maintains a synchronous cache:

```dart
Authyra.instance.currentUser        // AuthUser?   no await
Authyra.instance.isAuthenticated    // bool        no await
Authyra.instance.currentState       // AuthState   no await
```

Safe to call in `build()` methods without `FutureBuilder`.
