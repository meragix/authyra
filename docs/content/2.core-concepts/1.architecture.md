## The Big Picture

Authyra is built on three core principles:

### 1. Separation of Concerns

```
Authentication Logic  ≠  Navigation Logic
```

Authyra handles:
- ✅ Authentication state
- ✅ Session management
- ✅ Provider orchestration
- ✅ Storage abstraction

Your app handles:
- ✅ Where to navigate
- ✅ How to display UI
- ✅ Business logic

### 2. Reactive by Default

Everything in Authyra is reactive:

```dart
// Listen to auth changes
Authyra.instance.onAccountChanged.listen((account) {
  if (account == null) {
    // User logged out
  } else {
    // User logged in or switched account
  }
});
```

Your UI automatically updates when auth state changes.

### 3. Platform Agnostic

The core `authyra` package works everywhere:

```
Flutter Apps     ✅
Dart Backend     ✅
CLI Tools        ✅
Scripts          ✅
```

```

│                    APPLICATION LAYER                        │

                          ↓ uses

                          ↓ uses

                          ↓ delegates to

```

## Data Flow

### Sign In Flow

```
1. User enters credentials in UI
   ↓
2. UI calls Authyra.instance.signIn()
   ↓
3. AuthyraInstance delegates to AuthyraClient
   ↓
4. AuthyraClient finds the correct provider
   ↓
5. Provider validates credentials (calls your backend)
   ↓
6. Provider returns AuthAccount
   ↓
7. AuthyraClient saves to storage
   ↓
8. AuthyraClient returns account to AuthyraInstance
   ↓
9. AuthyraInstance updates internal state
   ↓
10. AuthyraInstance emits event in stream
   ↓
11. AuthyraScope receives stream event
   ↓
12. AuthyraScope calls setState()
   ↓
13. InheritedWidget notifies dependents
   ↓
14. AuthGuard rebuilds, sees isAuthenticated = true
   ↓
15. UI shows authenticated screen
```

### Sign Out Flow

```
1. User clicks logout button
   ↓
2. UI calls context.authSignOut() or Authyra.instance.signOut()
   ↓
3. AuthyraInstance delegates to AuthyraClient
   ↓
4. AuthyraClient clears storage
   ↓
5. AuthyraInstance sets currentAccount = null
   ↓
6. AuthyraInstance emits null in stream
   ↓
7. AuthyraScope rebuilds
   ↓
8. AuthGuard sees isAuthenticated = false
   ↓
9. UI shows login screen
```

## Key Components

### AuthyraClient

**Role**: Pure business logic, no global state

```dart
final client = AuthyraClient(
  providers: [EmailAuthProvider()],
  storage: InMemoryAuthStorage(),
);

// Use directly in backend
final account = await client.signIn(...);
```

**Use when**:
- Building backend APIs
- Writing tests
- Need multiple independent auth contexts

### AuthyraInstance

**Role**: Global singleton with reactivity

```dart
// Configure once
Authyra.instance.configure(client);

// Use everywhere
final isAuth = Authyra.instance.isAuthenticated;
Authyra.instance.onAccountChanged.listen(...);
```

**Use when**:
- Building Flutter apps
- Need global auth state
- Want reactive updates

### AuthyraScope

**Role**: Propagate auth state through widget tree

```dart
AuthyraScope(
  child: MaterialApp(...),
)
```

**Provides**:
- `context.auth` - Access current state
- `context.activeAccount` - Current account
- `context.isAuthenticated` - Auth status
- `context.switchToAccount()` - Switch accounts
- `context.authSignOut()` - Sign out

## Design Decisions

### Why Two Packages?

**authyra** (pure Dart):
- Works on backend, CLI, scripts
- No Flutter dependency
- Smaller, faster to test

**flutter_authyra** (Flutter):
- UI components
- BuildContext extensions
- Only for Flutter apps

### Why Singleton + Client?

**Client** = testable, injectable, pure logic  
**Instance** = convenient, reactive, global access

You get the best of both worlds:
- Easy to test (use AuthyraClient)
- Easy to use (use Authyra.instance)

### Why Streams?

Streams are the foundation of reactive programming in Dart:
- Native to Dart ecosystem
- Work with StreamBuilder
- Work with any state management (Bloc, Riverpod, etc.)
- Low overhead
