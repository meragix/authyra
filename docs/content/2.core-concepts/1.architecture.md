## The Big Picture

Authyra is built on three core principles:

**1. Separation of Concerns** — authentication logic lives in pure Dart, completely independent of UI and navigation.

**2. Reactive by Default** — every state change is surfaced as a `Stream`. Wire it to anything: `StreamBuilder`, Riverpod, Bloc, GoRouter, or your own listener.

**3. Platform Agnostic** — the core `authyra` package imports nothing from Flutter. It runs on mobile, web, desktop, backend (Shelf, Dart Frog), and CLI tools identically.

## Two-Layer Design

```text
┌─────────────────────────────────────────────────────────────┐
│  AuthyraClient                                              │
│  Stateless orchestrator — no global state, fully testable   │
│                                                             │
│  ┌───────────────┐  ┌──────────────┐  ┌──────────────────┐ │
│  │  AuthProvider  │  │  AuthStorage │  │  SessionManager  │ │
│  │  (interface)   │  │  (interface) │  │  multi-account   │ │
│  └───────────────┘  └──────────────┘  └──────────────────┘ │
└──────────────────────────────┬──────────────────────────────┘
                               │ wrapped by
┌──────────────────────────────▼──────────────────────────────┐
│  AuthyraInstance  (typedef alias: Authyra)                  │
│  Singleton — global access, sync state cache, streams       │
│                                                             │
│  currentUser        AuthUser?          (synchronous)        │
│  currentState       AuthState          (synchronous)        │
│  isAuthenticated    bool               (synchronous)        │
│  authStateChanges   Stream<AuthState>  (broadcast)          │
│  sessionStream      Stream<AuthSession?> (broadcast)        │
│  accounts           AccountManager    (multi-account)       │
└─────────────────────────────────────────────────────────────┘
```

The two layers solve different problems:

| Layer | Role | Use it when |
| ----- | ---- | ----------- |
| `AuthyraClient` | Pure business logic, injectable | Writing tests, backend APIs, or multiple independent auth contexts |
| `AuthyraInstance` | Singleton with reactive streams and sync state cache | Building apps that need global auth state |

## Component Overview

### AuthyraClient

The workhorse. It:
- Registers `AuthProvider` instances (by `id` slug).
- Delegates `signIn` / `signOut` / `refreshSession` to the matching provider.
- Persists and loads `SessionRegistry` via `AuthStorage`.
- Exposes `authStateStream` and `sessionStream` as broadcast streams.
- Exposes `AccountManager` for multi-account operations.

```dart
final client = AuthyraClient(
  providers: [
    CredentialsProvider.withTokens(id: 'email', authorize: myCallback),
    GoogleProvider(clientId: 'YOUR_CLIENT_ID'),
  ],
  storage: InMemoryAuthStorage(), // or SecureAuthStorage()
);

// Pure: no singleton, no global side effects.
await client.initialize();
final user = await client.signIn('email', params: {...});
```

### AuthyraInstance

Singleton wrapper. One per process. Access via `Authyra.instance` (or the `Authyra` typedef directly):

```dart
await Authyra.initialize(client: client); // must be called once

// Synchronous — safe to call in build() without await
Authyra.instance.currentUser        // AuthUser?
Authyra.instance.isAuthenticated    // bool

// Async accessors — reach into storage if memory cache is stale
await Authyra.instance.getSession()      // AuthSession?
await Authyra.instance.getAccessToken()  // String?

// Reactive
Authyra.instance.authStateChanges.listen((state) { ... });
```

### AuthProvider

The extension point. Every authentication strategy implements this interface:

```dart
abstract class AuthProvider {
  String get id;          // unique slug, e.g. 'google'
  bool get supportsRefresh => false;
  bool get supportsSignOut => false;

  Future<AuthSignInResult?> signIn({Map<String, dynamic>? params});
  Future<void> signOut({String? userId}) async {}
  Future<AuthTokenResult?> refreshToken(String refreshToken) async => null;
}
```

Built-in providers in v0.1.0:

| Provider | Type | Notes |
| -------- | ---- | ----- |
| `CredentialsProvider` | credentials | User profile only |
| `CredentialsProvider.withTokens` | credentials | JWT backend — stores tokens |
| `OAuth2Provider` | oauth2 | Authorization Code + PKCE |
| `GoogleProvider` | oauth2 | Prebuilt — wraps OAuth2Provider |
| `GitHubOAuth2Provider` | oauth2 | Prebuilt — no PKCE (GitHub limitation) |
| `ProxyOAuthProvider` | oauth2 | Backend-delegated — client secret never in app |

### AuthStorage

Pluggable persistence interface. The core package ships:

- `InMemoryAuthStorage` — for tests and development (not persisted across restarts)
- `AuthStorage` abstract class — implement once, swap anytime

```dart
abstract class AuthStorage {
  Future<void>         initialize();
  Future<String?>      read(String key);
  Future<void>         write(String key, String value);
  Future<bool>         delete(String key);
  Future<void>         clear();
  Future<bool>         containsKey(String key);
  Future<List<String>> getKeysWithPrefix(String prefix);
}
```

### SessionManager

Internal component — you won't use this directly. It:
- Serialises/deserialises `SessionRegistry` (the in-memory account map) to/from `AuthStorage`.
- Uses an `_AsyncMutex` to serialise concurrent writes and prevent race conditions.
- Exposes `cleanExpiredSessions()` for housekeeping.

### AccountManager

Multi-account API, accessible via `Authyra.instance.accounts`:

```dart
final mgr = Authyra.instance.accounts;

await mgr.getAll();           // List<AuthUser> — all signed-in users
await mgr.switchTo(userId);   // Activate a different account
await mgr.signOut(userId);    // Sign out one account
await mgr.signOutAll();       // Clear every session
await mgr.cleanExpired();     // Remove expired sessions, returns count
```

## Data Flow

### Sign In

```text
signIn('email', params: {...})
    │
    ├─ AuthyraClient._assertInitialized()
    ├─ _providerMap['email'].signIn(params)     ← your callback
    │      returns AuthSignInResult
    ├─ Build AuthSession from result
    ├─ SessionManager.saveSession(session)
    ├─ _authStateController.add(AuthState.authenticated(user))
    └─ AuthyraInstance._currentState = new state
           └─ _stateController.add(state)       ← authStateChanges emits
```

### Sign Out

```text
signOut()
    │
    ├─ SessionManager.getActiveSession()
    ├─ provider.signOut() if supportsSignOut
    ├─ SessionManager.clearActiveSession()
    └─ _authStateController.add(AuthState.unauthenticated())
           └─ authStateChanges emits
```

### Token Refresh

```text
refreshSession()
    │
    ├─ SessionManager.getActiveSession()
    ├─ provider.refreshToken(session.refreshToken)
    │      returns AuthTokenResult
    ├─ AuthSession.refreshed(result) → new session
    ├─ SessionManager.updateSession(userId, newSession)
    └─ _authStateController.add(AuthState.authenticated(user))
```

## Key Models

### AuthState

Emitted by `authStateChanges`. Extends `Equatable` — identical consecutive states are deduplicated so your stream won't trigger spurious rebuilds.

```dart
enum AuthStateType { authenticated, unauthenticated, error }

class AuthState {
  final AuthStateType type;
  final AuthUser? user;    // non-null when authenticated
  final String? error;     // non-null when type == error

  bool get isAuthenticated => type == AuthStateType.authenticated;

  factory AuthState.authenticated(AuthUser user) { ... }
  factory AuthState.unauthenticated() { ... }
  factory AuthState.error(String message) { ... }
}
```

### AuthSession

Stored in `SessionRegistry`. Carries user identity + tokens + expiry:

```dart
class AuthSession {
  final AuthUser   user;
  final String?    accessToken;
  final String?    refreshToken;
  final DateTime?  expiresAt;
  final DateTime   createdAt;
  final DateTime   lastUsedAt;

  bool get isExpired   => expiresAt != null && DateTime.now().isAfter(expiresAt!);
  bool get shouldRefresh => ...;  // true when within refresh threshold
}
```

### AuthUser

Immutable user profile. Extend via `metadata`:

```dart
AuthUser(
  id:        'usr_01j...',
  email:     'alice@example.com',
  name:      'Alice',
  avatarUrl: 'https://...',
  metadata:  {'role': 'admin', 'plan': 'pro'},
)
```

## Design Decisions

### Why no Flutter dependency in core?

- Tests run with plain `dart test` — no widget test runner, no platform channels.
- The same `AuthyraClient` instance can be shared between a Flutter app and a Dart backend in a monorepo.
- Smaller pub.dev bundle; consumers opt into Flutter widgets separately (v0.3.0).

### Why Singleton + Client?

**Client** = injectable, no side effects, ideal for tests and backend.
**Instance** = convenient global access, sync state cache, reactive streams.

You get both: use `AuthyraClient` in tests, use `Authyra.instance` in your app.

### Why Streams instead of ChangeNotifier?

- Native to Dart — no framework dependency.
- Compatible with every state management solution: `StreamBuilder`, Riverpod, Bloc, RxDart.
- `Equatable` on `AuthState` gives free deduplication without manual `==` checks.

### Why immutable SessionRegistry?

`SessionRegistry` is a value object (immutable map of sessions). Every mutation returns a new registry and atomically writes it to storage. This eliminates a whole class of race conditions — there is no "partial write" state.
